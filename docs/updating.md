# サイトの更新のしかた

ブログの記事を追加する手順と、トップページの「おすすめ商品」を入れ替える手順です。
どちらも、決まった場所にファイルを足したり直したりして、GitHub に送る（push する）と反映されます。

> 作業の前に、手元のリポジトリを最新にしてください（`git pull`）。README の進捗表は GitHub 上で自動更新されるためです。

## 1. ブログの記事を追加する

### 1-1. 記事の番号を決める

記事の番号は URL になります（番号 258 なら `/258/`）。次のコマンドで、使える番号が表示されます。

```text
npm run blog:next-id
```

### 1-2. 記事のフォルダとファイルを作る

`src/content/blog/` の中に、番号の名前のフォルダを作り、その中に `index.md` を作ります。
写真も同じフォルダに入れます。

```text
src/content/blog/
└── 258/
    ├── index.md      ← 記事
    ├── hero.jpg      ← 一覧やトップに出る写真（なくてもよい）
    └── photo-1.jpg   ← 本文に入れる写真（なくてもよい）
```

### 1-3. index.md を書く

```markdown
---
title: 春の催事に出店します
date: 2026-11-10T10:00:00+09:00
categories: [news, exhibit]
hero: ./hero.jpg
heroAlt: 催事の会場に並べた張り子の干支
---

11月15日（土）に、開成山公園の催事に出店します。

![ブースに並べた赤べこ](./photo-1.jpg)

オンラインショップでも[同じ商品](https://wakuya.shop-pro.jp/?pid=177769621)をお求めいただけます。
```

`---` で囲んだ部分に、記事の情報を書きます。

| 項目 | 書くこと | 必須 |
|------|----------|------|
| `title` | 記事のタイトル | ○ |
| `date` | 公開する日時。`2026-11-10T10:00:00+09:00` の形（最後の `+09:00` は日本時間の意味） | ○ |
| `categories` | カテゴリ。`[ ]` の中にカンマ区切りで1つ以上 | ○ |
| `hero` | 一覧やトップに出る写真のファイル名（`./` を付ける） | |
| `heroAlt` | その写真に何が写っているかの説明（目の不自由な方の読み上げに使う）。`hero` を書いたら必須 | |
| `description` | 検索結果に出る説明。書かなければ本文の最初の部分から自動で作る | |
| `draft` | `true` にすると公開しない（下書き） | |

使えるカテゴリ：

| 書くもの | 画面の表示 |
|----------|------------|
| `news` | お知らせ |
| `folk_craft` | 民芸品について |
| `column` | 店主のコラム |
| `exhibit` | 出展について |
| `etc` | その他 |

本文の書き方：

- 段落と段落の間は1行空けます
- 段落の中で改行したいときは、行の最後に `\` を付けます
- **太字**にしたい言葉は `**` で囲みます
- 写真は `![写真の説明](./ファイル名)` と書きます。説明は空にしないでください
- リンクは `[表示する文字](URL)` と書きます
- 見出しを入れたいときは `## 見出し` と書きます（`#` 1つは記事のタイトルに使っているので使いません）
- 未来の日時を `date` に書いた記事は、その日時より後にサイトが作り直されたときに公開されます

### 1-4. 手元で確認する

```text
npm run build
npm run preview
```

http://localhost:4321/ を開き、次の5か所に記事が出ていることを確かめます。

1. 記事のページ（`/258/`）
2. ブログ一覧（`/blogs/`）の先頭
3. 選んだカテゴリの一覧（`/category/news/` など）
4. トップページの「お知らせ」の先頭
5. サイトマップ（`dist/sitemap-0.xml` に `/258/` がある）

### 1-5. うまくいかないとき

`npm run build` が失敗したときは、エラーの文章に記事の番号（`blog → 258` の形）と項目名が出ます。

| エラーに出る言葉 | 原因と直し方 |
|------------------|--------------|
| `title が空です` | `title` が書かれていない |
| `categories` と `Invalid option` | カテゴリの書き方が違う（上の表の英語で書く） |
| `heroAlt（写真の説明）も書いてください` | `hero` を書いたのに `heroAlt` がない |
| `image-not-found`（写真が見つからない） | 写真のファイル名が違う、または写真をフォルダに入れていない |
| `記事のディレクトリ名は数字にしてください` | フォルダの名前に数字以外が入っている |

### 1-6. 公開する

作ったファイルをコミットして、機能ブランチから develop へ pull request を出します（開発の流れは README）。
画面テストが通ったらマージします。

## 2. おすすめ商品を入れ替える

トップページと記事ページの「おすすめ商品」は、`src/data/recommended.ts` の1つのファイルで管理しています。

1. 商品の写真（正方形がきれいに見えます）を `src/assets/recommend/` に入れます
2. `src/data/recommended.ts` の上のほうに、写真を読み込む行を足します

   ```ts
   import kokeshi from '../assets/recommend/kokeshi.png';
   ```

3. 下の `recommended` の一覧の、入れ替えたい行を書き換えます

   ```ts
   { name: '土湯こけし', image: kokeshi, alt: '赤い着物の柄の土湯こけし', url: 'https://wakuya.shop-pro.jp/?pid=123456789' },
   ```

   | 項目 | 書くこと |
   |------|----------|
   | `name` | 画面に出す商品名 |
   | `image` | 2 で読み込んだ名前 |
   | `alt` | 写真に何が写っているかの説明 |
   | `url` | カラーミーショップの商品ページの URL（商品ページを開いたときのアドレス） |

   価格や在庫はここに書きません（カラーミーショップの表示を正とするため）。

4. リンク先が正しいか確かめます。カラーミーショップに実際にアクセスして、ページがあるかを調べます

   ```text
   npm run check:shop-links
   ```

   「リンク先が見つからない URL」と出たら、その URL を直してください。
   「警告：記事の本文のリンク先が見つかりません」は、過去の記事の中のリンクです。直すかどうかはお店で決めてください。

5. 1-4 と同じように手元で確認し、1-6 と同じように公開します

「もっと見る」のリンク先（`recommendedMoreUrl`）も同じファイルにあります。
