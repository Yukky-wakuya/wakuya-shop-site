# Feature Specification: 固定ページ（わくや概要・わくやの想い・出張わくや・お問い合わせ）

**Feature Branch**: `003-fixed-pages`

**Created**: 2026-11-04

**Status**: Draft

**Input**: User description: "固定ページ4つ（わくや概要 /summary/、わくやの想い /thought/、出張わくや /deliver/、お問い合わせ /contact/）を新しいサイトに作る。文章・写真・構成は現行(https://waku-8.com/)を踏襲し、URL は現行と同じにする。002 の下層ページの部品（曲線の写真の見出し部分など）と共通レイアウトを使い、ナビとフッターのリンク切れをなくす。お問い合わせは静的サイトのまま実現する。各ページに固有の title・description・構造化データを付け、url-mapping.md を更新する"

## Clarifications

### Session 2026-11-04

- Q: お問い合わせページをどう作るか（現行のフォームは WordPress のサーバー機能で動き、静的サイトでは動かない） → A: メールと電話の案内にする。入力フォームは作らない（後から足せるようにしておく）。
- Q: 営業時間と定休日をどうするか（ブログ `/251/` に、2026年3月30日で実店舗の営業を終え、所在地は事務所になったとある） → A: 概要・フッター・構造化データから営業時間と定休日を外す。住所は事務所と分かる形にし、電話・メール・オンラインショップは残す。文言は公開前に店が確認する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - お店に連絡する方法が分かる (Priority: P1)

お客様や催事の主催者が「お問い合わせ」を開くと、メールと電話で連絡する方法がすぐに分かり、スマートフォンならそのままメールを書いたり電話をかけたりできる。

**Why this priority**: ナビとブログの案内（`/251/`）から来る人の行き先で、連絡手段がなければ機会を失う。リンク切れの解消としても最も影響が大きい。

**Independent Test**: `/contact/` を開き、メールと電話のリンクが正しい宛先になっていることを確かめる。

**Acceptance Scenarios**:

1. **Given** お問い合わせページ, **When** メールアドレスを選ぶ, **Then** `shop@waku-8.com` 宛てのメールの作成画面が開く
2. **Given** スマートフォンでお問い合わせページ, **When** 電話番号を選ぶ, **Then** `024-922-1250` への発信画面が開く
3. **Given** JavaScript が動かない環境, **When** お問い合わせページを開く, **Then** メールアドレスと電話番号が文字で読める

---

### User Story 2 - お店がどんな店で、今どう営んでいるかが分かる (Priority: P1)

お客様が「わくや概要」を開くと、店の紹介文、会社の情報、沿革が読める。営業時間のような、閉店前の情報を見て誤って来店することがない。

**Why this priority**: 店の基本情報は検索や AI の回答の元になる。古い情報が残ると、お客様に実害が出る。

**Independent Test**: `/summary/` を開き、紹介文・会社情報・沿革が現行と一致し、営業時間と定休日が出ていないことを確かめる。全ページのフッターと構造化データも確かめる。

**Acceptance Scenarios**:

1. **Given** わくや概要, **When** 開く, **Then** 紹介文・会社情報の表（屋号・会社名・代表・住所・TEL／FAX・メール・ウェブショップ）・沿革が出て、営業時間と定休日は出ない
2. **Given** 任意のページのフッターと構造化データ, **When** 確かめる, **Then** 営業時間が含まれず、住所が事務所と分かる
3. **Given** わくや概要の「店主のコラム」, **When** 表示する, **Then** 店主のコラムの記事が出て、「もっと見る」で店主のコラムの一覧へ移動する

---

### User Story 3 - 店の想いと歩みを読める (Priority: P2)

お客様が「わくやの想い」を開くと、現行と同じ4つの章の文章を、写真と色の模様とともに読める。下には、おすすめ商品とオンラインショップへの導線がある。

**Why this priority**: 店の個性を伝えるページで、トップページの「もっと見る」の行き先でもある。ただし連絡先や基本情報より後でよい。

**Independent Test**: `/thought/` を開き、4つの章の見出しと本文が現行と一致し、スマートフォン幅で文章と模様が重なって読めなくならないことを確かめる。

**Acceptance Scenarios**:

1. **Given** わくやの想い, **When** 開く, **Then** 4つの章が現行の順で、現行と同じ文章で読める
2. **Given** 幅 360px, **When** 開く, **Then** 横スクロールがなく、見出しの文字が背景の模様と重なっても読める
3. **Given** わくやの想いの下部, **When** 商品を選ぶ, **Then** カラーミーショップの商品のページが開く

---

### User Story 4 - 出張わくやを知り、依頼できる (Priority: P2)

マルシェやイベントの主催者が「出張わくや」を開くと、出張販売の案内と過去の出張の様子が分かり、そこから依頼の連絡先へ進める。

**Why this priority**: 実店舗を閉じた後の中心の活動の一つで、依頼の導線が商いに直結する。現行では依頼のリンクが動いていない。

**Independent Test**: `/deliver/` を開き、依頼のリンクで `/contact/` へ移動でき、「今までの出張風景」に「出展について」の記事が出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 出張わくや, **When** 「マルシェ・イベントなどの出張依頼はこちら」を選ぶ, **Then** お問い合わせページへ移動する
2. **Given** 「今までの出張風景」, **When** 表示する, **Then** 「出展について」の記事が新しい順に出て、「もっと見る」でそのカテゴリの一覧へ移動する

---

### Edge Cases

- **ナビ・フッターの確認**：`/summary/`・`/thought/`・`/deliver/`・`/contact/` を作ったら「まだ作っていないページ」の一覧から消し、リンク切れのテストで失敗として扱う。
- **現行のプライバシーポリシー（`/privacy/`）**：フォームをなくし、フッターはカラーミーショップのプライバシーポリシーへリンクしているため、本機能では作らない。対応表には理由を書いて残す。
- **「店主のコラム」「今までの出張風景」の記事が0件のとき**：その部分を出さない。
- **ブログの記事に残る古い情報**（年末年始の営業案内や、閉店前の記事など）：過去の記録のため変えない。
- **メールソフトがない端末**：メールアドレスを文字で読め、コピーできる。

## Requirements *(mandatory)*

### Functional Requirements

**共通**

- **FR-001**: `/summary/`・`/thought/`・`/deliver/`・`/contact/` を現行と同じ URL で公開しなければならない。
- **FR-002**: 各ページは共通レイアウトと、002 の下層ページの見出し部分を使わなければならない。写真と模様の色は現行のページごとのものにする。
- **FR-003**: 文章は現行のまま移さなければならない。変えるのは「現行サイトからの変更」に記録したものだけとする。
- **FR-004**: 各ページに固有の title・description・canonical・OGP と、パンくずリストの構造化データを付けなければならない。わくや概要には会社の情報を示す構造化データ（AboutPage）、お問い合わせには連絡先を示す構造化データ（ContactPage）を付ける。内容は画面の表示と一致させる。
- **FR-005**: 見出しは h1 から順に論理的な構造にし、現行で画像だけが表していた情報は文字でも伝えなければならない。縦書きや模様の上の文字も、読み上げの順が読む順と一致しなければならない。
- **FR-006**: 4ページを画面テスト（スクリーンショット比較・アクセシビリティ・リンク切れ・SEO）の対象に加え、「まだ作っていないページ」の一覧を空にしなければならない。
- **FR-007**: `docs/current-site/url-mapping.md` の該当の行を更新し、`/privacy/` は対応を決めて理由を書かなければならない。
- **FR-008**: 新しい部品はデザイントークンを参照し、スタイルガイドに加えなければならない。

**お問い合わせ**

- **FR-009**: お問い合わせページには、メールアドレスと電話番号を文字とリンクで表示しなければならない。値は店舗情報の1か所から取る（開発原則VI）。
- **FR-010**: サイト側で個人情報を受け取ったり保存したりしてはならない。入力フォームは作らない。

**店舗情報**

- **FR-011**: 営業時間と定休日を、わくや概要・フッター・構造化データから外さなければならない。
- **FR-012**: 住所は、事務所の所在地と分かる表記にしなければならない（`/251/`：「有限会社和久屋 事務所」「郡山市中町10-14 和久屋ビル」）。
- **FR-013**: 公開の前に店が確認する店舗情報の文言を、確認項目として記録しなければならない。

**わくや概要**

- **FR-014**: 紹介文、会社情報の表、沿革、オンラインショップの帯、店主のコラムの記事（最新4件まで）を現行の順で表示しなければならない。
- **FR-015**: 店主のコラムの「もっと見る」は `/category/column/` へリンクしなければならない。

**わくやの想い**

- **FR-016**: 4つの章（はじまりは／会社から毎日／有限会社和久屋は／郡山のフロンティアスピリット）を、現行の文章・写真・模様で現行の順に表示し、そのあとにオンラインショップの帯とおすすめ商品を表示しなければならない。

**出張わくや**

- **FR-017**: 案内文、写真、依頼へのリンク（`/contact/`）、今までの出張風景（「出展について」の記事を最新4件まで）を現行の順で表示し、「もっと見る」は `/category/exhibit/` へリンクしなければならない。

### Key Entities

- **店舗情報（Store）**：屋号・会社名・代表・事務所の住所・電話番号・メール・ウェブショップ。全ページのフッター・構造化データ・概要・お問い合わせの共通の元データ。営業時間は持たない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: サイト内のリンク切れが0件で、「まだ作っていないページ」の一覧が空である。
- **SC-002**: 4ページの本文が、「現行サイトからの変更」に書いたものを除いて現行と一致する。
- **SC-003**: 営業時間と定休日の表示が全ページ（過去のブログ記事の本文を除く）で0件である。
- **SC-004**: 4ページが幅 360px・768px・1280px で横スクロールなしに表示され、アクセシビリティの自動チェックで違反が0件である。
- **SC-005**: スマートフォンで、お問い合わせページを開いてから1回の操作でメールの作成または電話の発信を始められる。
- **SC-006**: 4ページを Lighthouse（モバイル）で測り、Performance・Accessibility・Best Practices が90点以上である。SEO はテスト公開の noindex を除いて90点以上である。

## 現行サイトからの変更

開発原則I により、現行サイトから変える点を記録する。

| 現行の状態 | 変更内容 | 変更理由 |
|------------|----------|----------|
| お問い合わせは入力フォーム | メールと電話の案内にする | 静的サイトでサーバーの処理を持たず、サイト側で個人情報を預からないため（原則II） |
| 概要に営業時間・定休日。001 でフッターにも追加 | 概要・フッター・構造化データから外す | 2026年3月30日で実店舗の営業を終えた（`/251/`）。情報が古い |
| 住所が店舗の所在地の表記 | 事務所と分かる表記にする | 同上 |
| 概要「店主のコラム」の「もっと見る」が `/category/news/` | `/category/column/` にする | 見出しと行き先が合っていない |
| 出張依頼のリンクの行き先が空（`http://`） | `/contact/` にする | リンクが動いていない |
| 出張わくやの本文「詰め込んお伺いいたします」 | 「詰め込んでお伺いいたします」にする | 明らかな誤字 |
| 見出しが h2 から始まる（ページ名）、章が h3 | ページ名を h1、章を h2 にする | 原則VIII の見出しの構造 |
| 出張依頼のボタンがオレンジの地に白文字（コントラスト 2.21） | 文字を黒にする（9.51） | 原則IV（WCAG AA 4.5 以上） |
| 飾りの画像に空でない alt（「タイトルアイコン」など） | 装飾は読み上げない | 原則IV |
| わくやの想いの本文の下地がスマートフォンでも灰色の模様 | スマートフォンは生成り色の角丸の面にする（PC は現行の模様） | 模様を置くと本文の幅が足りず、横にはみ出すため（原則IV） |
| わくやの想いの「有限会社和久屋は、」の下地の模様の幅（46%） | 54% に広げる | 本文が模様の外に出るため |
| わくやの想いの見出しの模様の幅（277px） | 320px まで広げる | 見出しの白い文字が模様の外に出ると読めないため（原則IV） |
| 「上へ戻る」の固定ボタン | 作らない | 001 と同じ |

## Assumptions

- 文章・写真は現行のページから取得する。写真の権利は 002 と同じく仮に使い、main へのマージ前に店が確認する。
- 沿革の「今年2023年は」など、書かれた時点の文章は現行のまま残す。古いと店が判断すれば後で直す。
- `shop@waku-8.com` と `024-922-1250` は現在も連絡がつくものとし、公開前に店が確認する。
- 電話番号は `/251/` の案内（不在時は携帯へ転送、または折り返し）を添えて案内する。
- 営業時間を持たないことは、開発原則VIII の構造化データ（営業時間）と食い違うが、存在しない営業時間を書かないことを優先し、計画に理由を記録する。
- テスト公開と本番の切り替えは 002 のとおりで、本機能では変えない。
