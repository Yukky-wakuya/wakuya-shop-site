# ドメイン（waku-8.com）とメールの引き継ぎ

`waku-8.com` は、ウェブサイトとメール（`shop@waku-8.com`）の両方で使っています。今は、現行サイトを管理している会社の契約（ムームードメイン・ロリポップ）で動いています。
引き継ぎの全体の流れと、管理会社から受け取るものは [handover.md](handover.md) にあります。

**方針（2026-11-24 決定）：できるかぎり Cloudflare にまとめる。**

| 役割 | 今 | 引き継ぎ後 |
|------|----|------------|
| ドメインの登録 | ムームードメイン（管理会社の契約と思われる） | **Cloudflare Registrar**（§5。費用は登録料の原価だけ） |
| DNS | ロリポップ（ムームーDNS） | **Cloudflare**（§3 の A・B） |
| ウェブ | ロリポップの WordPress | **Cloudflare Pages**（§3 の C、[deploy.md](deploy.md) §3） |
| メールの受け取り | ロリポップのメールボックス | **Cloudflare Email Routing** で店の Gmail に転送（§4） |
| メールの送信 | ロリポップ | 店の Gmail から `shop@waku-8.com` として送る（§4） |

順番は、DNS → ウェブ → メール → ドメインの移管 → ロリポップの解約、です。**メールの切り替えを確かめるまで、ロリポップは解約しません。**

## 1. 大事なこと

- **メールの切り替えを確かめる前にロリポップを解約すると、メールが止まります。** 解約は §6 まで待ちます。
- **ドメインの期限が切れると、サイトもメールも止まります。** 期限は 2027-10-05 です。移管（§5）が済むまでは、管理会社に更新をお願いしておきます。
- Cloudflare Pages で `waku-8.com`（`www` なし）を使うには、ネームサーバーを Cloudflare に移す必要があります（Cloudflare の決まり）。
- DNS を移すときは、メールの設定（MX・SPF・DMARC・`mail`）を **そのまま写します**。値を変えなければ、メールの送受信に影響はありません。
- ドメイン・Cloudflare のアカウントの持ち主は、**有限会社和久屋**にします。制作に関わる人は、Cloudflare のアカウントのメンバーとして加わります。

## 3. DNS とウェブ

段階を分けて、1つずつ確かめながら進めます。**ステップ B では見た目もメールも何も変わりません。** ウェブが切り替わるのはステップ C です。

### A. Cloudflare に DNS を用意する（まだ何も変わらない）

1. Cloudflare の管理画面 →「Add a domain」→ `waku-8.com` を入力し、Free プランを選ぶ
2. Cloudflare が今のレコードを読み込むので、下の表と、管理会社から受け取った一覧と照らし合わせ、足りないものを足し、違うものを直す

   | 種類 | 名前 | 値 | プロキシ |
   |------|------|----|----------|
   | A | `waku-8.com` | `157.7.107.26` | DNS のみ（灰色の雲） |
   | A | `www` | `157.7.107.26` | DNS のみ |
   | A | `mail` | `157.7.107.26` | **DNS のみ（必ず。オレンジにするとメールが使えない）** |
   | CNAME | `ftp` | `ftp.lolipop.jp` | DNS のみ |
   | MX | `waku-8.com` | `mx01.lolipop.jp`（優先度 10） | — |
   | TXT | `waku-8.com` | `v=spf1 include:_spf.lolipop.jp ~all` | — |
   | TXT | `_dmarc` | `v=DMARC1; p=none;` | — |

   - ウェブの2行（`waku-8.com`・`www`）も、この段階ではロリポップのままにする。切り替えは C で行う
   - SPF（`v=spf1` で始まる TXT）は1つだけにする。2つあるとメールが迷惑メール扱いされやすくなる
   - Email Routing はまだ有効にしない（§4 で行う）
3. Cloudflare が表示するネームサーバー2つ（`○○.ns.cloudflare.com`）を控える

### B. ネームサーバーを Cloudflare に移す

1. ムームードメインの管理画面 →「ネームサーバ設定変更」→「GMOペパボ以外のネームサーバを使用する」で、A-3 の2つを入れる（ムームードメインのログインを受け取っていないときは、管理会社に依頼する）
2. 反映には数時間〜最大 72 時間かかる。その間は古い DNS と新しい DNS のどちらが返っても、値が同じなので影響はない
3. Cloudflare の画面でドメインが「Active」になったら、次を確かめる
   - `npm run check:dns -- --phase after` で、**メールの4項目とネームサーバーが OK**（robots.txt はまだ旧サイトなので NG のままでよい）
   - 外のアドレス（携帯など）から `shop@waku-8.com` に送って届く。`shop@waku-8.com` から外へ送って届き、迷惑メールに入らない
   - 今の WordPress のサイトがいつもどおり見られる
4. うまくいかないときは、ネームサーバーを `uns01.lolipop.jp`・`uns02.lolipop.jp` に戻せば元どおりになる

### C. ウェブを新しいサイトに切り替える

[deploy.md](deploy.md) の §3 の手順で進めます。ここでは、DNS で追加でやることを書きます。

1. Pages のプロジェクト →「Custom domains」に `waku-8.com` を追加する。Cloudflare が、ウェブの A レコードを Pages 向けに置き換えてよいか聞いてくるので、許可する
2. `www.waku-8.com` も同じように追加する
3. `www` を `www` なしに転送する。ドメインの「Rules」→「Redirect Rules」→ テンプレートの「Redirect from WWW to root」を使い、301 にする
4. `mail`・`ftp`・MX・TXT のレコードには触らない
5. `npm run check:dns -- --phase after` が**すべて OK** になることを確かめる。あわせて、もう一度メールの送受信を試す

元に戻すときは、Custom domains から外し、A-2 の表のとおりウェブの2行を `157.7.107.26` に戻します。

## 4. メールを Cloudflare Email Routing に移す

Email Routing は、`shop@waku-8.com` に届いたメールを、店の Gmail に転送する無料の仕組みです。メールボックスは持たないため、**読む・送るのは Gmail で行います**。

### 先に知っておくこと

- **送信は Gmail のサーバーから出ます。** `waku-8.com` の送信認証（SPF・DMARC）とは一致しないため、相手によっては迷惑メールに入ったり、「gmail.com 経由」と表示されたりします。今の DMARC は `p=none`（認証に失敗しても受け取ってもらう設定）なので、届かなくなることはまずありません。**DMARC を `p=quarantine`・`p=reject` に強めてはいけません。**
  送信で困ることが続いたときは、送信だけ有料のサービスにするかを、そのとき決めます。
- **今のメールボックスの中身は、ロリポップを解約すると消えます。** 切り替えの前に、メールソフト（Thunderbird など）で IMAP でつないで、すべて取り込んで保存しておきます。
- `shop@` 以外に使っているアドレスがあれば、それぞれ転送の設定が要ります（管理会社から一覧を受け取る）。

### 手順

1. **バックアップ**：ロリポップのメールボックスの中身を保存する（上）
2. **転送先の登録**：Cloudflare のドメイン →「Email」→「Email Routing」→「Destination addresses」に店の Gmail を追加し、Gmail に届く確認メールのリンクを押す
3. **転送の設定**：「Routing rules」→「Custom addresses」で `shop@waku-8.com` → 店の Gmail を作る。ほかのアドレスも同じように作る。「Catch-all」（ほかのすべてのアドレス）は、迷惑メールが増えるので、使っていたアドレスが分からないときだけ一時的に有効にする
4. **切り替え**：「Enable Email Routing」を押す。Cloudflare が、ロリポップの MX と SPF を消して Cloudflare のものに置き換えてよいか聞いてくるので、許可する。`mail` の A レコードは、ロリポップを解約するまで残す
5. **確認**：
   - `npm run check:dns -- --phase after --mail cloudflare` がすべて OK
   - 外のアドレスから `shop@waku-8.com` に送り、Gmail に届く
   - 切り替えの直後は、DNS のキャッシュでしばらく（最大 1 日）ロリポップにも届くことがある。1 週間ほどは、ロリポップのメールボックスも毎日見る
6. **送信の設定**：Gmail の「設定」→「アカウントとインポート」→「他のメールアドレスを追加」で `shop@waku-8.com` を追加する。「エイリアスとして扱う」にチェックし、SMTP サーバーは `smtp.gmail.com`（ポート 587）、ユーザー名は店の Gmail のアドレス、パスワードは Google アカウントの「アプリ パスワード」を使う。`shop@waku-8.com` に届く確認メールで承認する。「返信時：メールを受信したアドレスから返信する」を選ぶ
7. **カラーミーショップの確認**：ショップから自動で送られるメール（注文の確認など）が、お客さまと店の両方に届くかを、テストの注文で確かめる

元に戻すときは、Email Routing を無効にし、§3 A-2 の表の MX と SPF を入れ直します（ロリポップを解約する前に限る）。

## 5. ドメインを Cloudflare Registrar に移す

Cloudflare Registrar は、登録料に上乗せをせずに原価で更新できるドメインの登録先です。移管の費用には 1 年分の更新が含まれ、有効期限は 1 年延びます。

**条件**：DNS が Cloudflare で動いていること（§3 の B が済んでいること）。

1. **管理会社に依頼すること**（[handover.md](handover.md) のメールに含めている）
   - ムームードメインで「Whois 代理公開」をやめる（代理公開のままだと、移管の承認メールが届かない）
   - ドメインのロックを外す
   - AuthCode（認証コード）を発行して渡す
2. Cloudflare の管理画面 →「Domain Registration」→「Transfer Domains」で `waku-8.com` を選び、AuthCode を入れて支払う。登録者の情報は、**有限会社和久屋**にする
3. 移管の承認のメールが、今の登録者のアドレスに届く。管理会社に承認してもらう（承認しなくても、5 日ほどで自動で移管される）
4. Cloudflare の画面で、ドメインが Cloudflare Registrar の管理になり、有効期限が 1 年延びたことを確かめる。**自動更新が有効**になっていることを確かめる

> 登録者の名義を変えると、60 日間ほかの登録先に移せなくなることがあります。名義の変更は、移管が済んでから Cloudflare で行うのが確実です。

## 6. 後片付け

- WordPress は、新しいサイトで問題がないと分かるまで（目安は 1 か月）ロリポップに残しておく。管理会社にバックアップ（ファイルとデータベース）をもらう
- §4 で 1 週間ほどロリポップにメールが届かなくなったことを確かめ、§5 の移管が済んだら、**管理会社にロリポップとムームードメインの解約を依頼する**
- 解約の後、Cloudflare の DNS から `mail` の A と `ftp` の CNAME を消す
